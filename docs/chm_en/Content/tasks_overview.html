Tasks at a glance

A task is a step that RFiDGear carries out on a chip, for example checking a UID, reading a sector, changing a key or writing a report. The tasks stand in a list (the project) and run from top to bottom.

The kinds of tasks

The dialogs of the chip tasks open only when a reader is connected.

Add and change a task

  1. Choose the task type in the menu Edit > Add / Edit Task(s), or in the context menu of the list (Add New Task).
  2. Set up the task in the dialog and confirm it.
  3. To change it, open a row with a double click or with Edit Task... in the context menu.

The order

The list is ordered by task number, and the tasks run from top to bottom, that is in ascending number. A click on a column heading changes only how the list is shown: the tasks still run in the order of their numbers, so a list that is shown in descending order does not run backwards. After you add or change a task, RFiDGear sorts the list again.

If you drag a row to another place with the mouse, the task gets the first free number between its new neighbours. If no number is free there, RFiDGear shows a warning (Task Index Update) and the row stays where it was.

Leave gaps when you number (10, 20, 30, ...), so that you can insert tasks in between later.

The execute condition

With an execute condition a task runs only if an earlier task ended with a certain result. You set two fields in the dialog:

  • Targeted Task Index: the number of the earlier task.
  • Target Result: the result it has to have.

If the earlier task had another result, RFiDGear skips the task. That is not an error. This is how you build branches: one task checks whether an application exists; a second one runs only if that check ended with Is Not True, and creates the application. The condition refers to a task that runs before this one.

The results of a task

Every task ends with a result. The icon in the list shows only succeeded or failed; the result itself is named by the selection fields of the execute condition and of the checkpoints.

ResultMeaning
No Errorsucceeded
Is Not Truea check answered "no": its condition did not hold. That is the answer of the check, not a fault of the reader or the card.
Is Not Falsethe counterpart, which can be chosen in conditions and checkpoints; no task of this version ends with it
Authentication Failedthe card refused the key
Permission Deniedthe card forbids this operation with the current access rights
Protocol Constraintthe reader or the card cannot do that, for example an NTAG on a PC/SC reader
Transport Errorthe connection broke, for example because the card was removed
Unknown Errorthe outcome is not known, for example when a block that was written does not read back as written
Out Of Memory Errorthere is no room left on the card
Key unavailablea key that the task names by a reference could not be fetched from its key store; no command was sent to the card for it. A failure of a SAM is another case. See Keys.
Card not expectedthe card on the reader is not the one the caller expects (Check UID with a variable)
Tasks that write to the chip change it without a question and without a way back. RFiDGear never repeats a write attempt on its own: if it stops, the result says what happened, and you decide how to go on.

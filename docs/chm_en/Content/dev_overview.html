Overview for developers

Part 2 of this help is for everyone who builds RFiDGear into their own software. It is a short version with reference tables. The full texts that it follows are in the source repository (see below); where this help and the files there differ, the files are right.

The principles

  • One attempt. RFiDGear never repeats on its own a command that changes a card (write, authenticate, format). A program that drives RFiDGear does not either: if RFiDGear does not say expressly "never started" after a doubt, ask for the result of the same job instead of sending it again.
  • One process, one user. One RFiDGear instance runs per Windows session. The pipe of external control can be reached only by the Windows user who started RFiDGear.
  • Contracts as assemblies. A client of external control uses RFiDGear.Bridge.Contracts.dll, an extension RFiDGear.Contracts.dll and RFiDGear.ExtensionSdk.dll; both groups keep the assembly version 1.0.0.0 so that programs built earlier keep binding. The public surface is held by approved snapshots in the tests.
  • Nothing secret in the protocol. RFiDGear writes no variable, path, UID, key or exception text of a client to its log.

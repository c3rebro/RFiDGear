Generic tasks: report, logic, program

These tasks need no chip. Add them with Edit > Add / Edit Task(s) > Add / Edit Generic (Non-Chip) Task.... The dialog has three tabs; the Task Type decides which one applies.

Create / Edit Report

A report fills the form fields of a PDF template. The page Reports (PDF) describes it in full; here are the fields of the dialog.

FieldMeaning
Report Template, Template Path, Open File...the PDF template. The button opens the file selection; the fields of the template then appear in the selection Template Field.
Checkpoint Setupa checkpoint says: "If the task with number N ended with the result E, write this content into the field". You set the Template Field, the Fieldvalue, the Targeted Task Index and the Targ. Err. Type (the expected result).
Add Checkpoint, Remove Checkpointadds the checkpoint you set up to the table or removes the selected one
Table of checkpointsthe columns CP Nr., Targeted Task-Index, Targeted Error-Level, Template Formfield and Formfield Content

Check Logic Block

A logic block has a list of checkpoints, each with a task number and an expected result, and a Logic Function. It ends with No Error if the function is fulfilled, otherwise with Is Not True. Other tasks can use the result in their execute condition.

Logic functionFulfilled when
ANDall checkpoints hold: every named task has the expected result
ORat least one checkpoint holds
Counter (OR)the number of checkpoints that hold fits the Counter Value: the Counter Operator is =, <, <=, > or >=
Comparethe Comparer Value (an expression) holds

An expression for Compare has the form operand operator value with the operators ==, !=, >= and <=:

OperandMeaning
$NAMEa variable of the run (see Start-up arguments), for example $EXPECTEDUID==04A1B2C3D4E5F6
%FREEMEMthe free memory of a DESFire card in bytes, for example %FREEMEM>=1024
%COUNTAPPSthe number of applications of a DESFire card
The logic functions NOT, NAND and NOR are in the selection but are not finished: do not use them.

Run Application

The field Path to Application (optional: with Arguments) takes the path of the program in quotation marks, then the arguments, for example "C:\Tools\notify.exe" -job $JOBNUMBER. RFiDGear replaces every $NAME in the arguments by the value of that variable of the run (for example from a start-up argument, see Start-up arguments). It starts the program and does not wait for it to end. The task counts as succeeded when the program was started; if the start fails, it ends with Is Not True.

The placeholders with a percent sign (%UID, %DATE, ...) are replaced in the fields of a report (see Reports), but not in the arguments of a program task in this version: they reach the program as they are typed. Pass such values as a $NAME variable.

If the path is %EXIT, the task closes RFiDGear. Use that as the last task of a project that another program started and that should not stay open afterwards.

A program that you enter here runs with the rights of the user who started RFiDGear. Do not open a project from an unknown source until you know its program tasks.

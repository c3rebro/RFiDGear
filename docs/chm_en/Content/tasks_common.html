Generic tasks: report, logic, program

These tasks need no chip. Add them with Edit > Add / Edit Task(s) > Add / Edit Generic (Non-Chip) Task.... The dialog has three tabs; the Task Type decides which one applies.

Task typeTabWhat for
Create / Edit ReportCreate / Edit Reportwrites a PDF form with values from the run

Create / Edit Report

A report fills the form fields of a PDF template. The page Reports (PDF) describes it in full; here are the fields of the dialog.

FieldMeaning
Report Template, Template Path, Open File...the PDF template. The button opens the file selection; the fields of the template then appear in the selection Template Field.
Checkpoint Setupthe table of the checkpoints. A checkpoint says: "If the task with number N ended with the result E, write this content into the field". You edit a checkpoint in the cells of its row.
Add Checkpoint, Remove CheckpointAdd Checkpoint adds a row, an empty one or a copy of the selected row (inserted after it); you then set its cells. Remove Checkpoint deletes the selected row.
The columnsCP Nr. (the order), Targeted Task-Index (choose the number of a task), Targeted Error-Level (choose the result it is to have), Template Formfield (choose a field of the template) and Formfield Content (type the content; the variables are on the page Reports)

Check Logic Block

A logic block has a list of checkpoints, each with a task number and an expected result, and a Logic Function. It ends with No Error if the function is fulfilled, otherwise with Is Not True. Other tasks can use the result in their execute condition.

Logic functionFulfilled when
ANDall checkpoints hold: every named task has the expected result
ORat least one checkpoint holds
Counter (OR)the number of checkpoints that hold fits the Counter Value: the Counter Operator is =, <, <=, > or >=
Comparethe Comparer Value (an expression) holds

An expression for Compare has the form operand operator value. Spaces around the three do not matter. These combinations exist:

OperandOperators that workMeaning
$NAME==, !=a variable of the run (see Start-up arguments), compared as text, for example $EXPECTEDUID==04A1B2C3D4E5F6. $NAME!= with nothing after it says that the variable is not empty
%FREEMEM>=, <=, ==, !=the free memory of a DESFire card in bytes, for example %FREEMEM>=1024. The value is a whole number: 4096, or 4.096, 4,096 or 4 096
%COUNTAPPS>=, <=, ==, !=the number of applications of a DESFire card, for example %COUNTAPPS==2

Every operator means what it says. An expression that cannot be evaluated ends with Is Not True, like one that is false, and the log says so (without the text of the expression). That is the case for: no operator, and an operand that RFiDGear does not know. For %FREEMEM and %COUNTAPPS also a value that is not a whole number and a run without a DESFire card. For a $NAME also >= and <=, and a variable that the run was not given (it is neither equal nor different; a variable that was given with an empty value does have a value, and $NAME== is true for it). A variable needs no card: $JOB==abc can be true without one.

Earlier versions of RFiDGear evaluated some of these wrongly: %FREEMEM!= tested for equality, %COUNTAPPS== and %COUNTAPPS!= tested for "at least", and %COUNTAPPS<= gave no result. A project that was written against that behavior has to be checked.
The logic functions NOT, NAND and NOR are in the selection but are not finished: do not use them.

Run Application

The field Path to Application (optional: with Arguments) takes the path of the program in quotation marks, then the arguments, for example "C:\Tools\notify.exe" -job $JOBNUMBER -uid %UID. RFiDGear replaces in the path and in the arguments every $NAME by the value of that variable of the run (for example from a start-up argument, see Start-up arguments; the case of the name does not matter) and these placeholders. It starts the program and does not wait for it to end. The task counts as succeeded when the program was started; if the start fails, it ends with Is Not True.

Placeholderis replaced by
%UID, %CHIPTYPEthe UID and the type of the card that the run read
%DATE, %DATETIMEthe date, DD/MM/YYYY, and the date with the time, in the notation of your Windows
%FREEMEM, %LISTAPPS, %COUNTAPPSthe free memory of a DESFire card, its application IDs (separated by commas) and their number

A value that is not known (the run read no card, or the card is no DESFire card) is replaced by nothing. The text of the task is not changed: every run replaces the placeholders again, with the values of its own card. What stands after the closing quotation mark of the path reaches the program as it was typed, quotation marks included.

If the path is %EXIT, the task closes RFiDGear when the project runs in the window, with AUTORUN or in the automatic mode of the menu. In a run that another program asks for (external control, an extension) it ends the run at that task instead and RFiDGear stays open: the tasks after it do not run, and they are not counted as failures. Use it as the last task of a project that was started with AUTORUN and should not stay open afterwards.

A program that you enter here runs with the rights of the user who started RFiDGear. Do not open a project from an unknown source until you know its program tasks.

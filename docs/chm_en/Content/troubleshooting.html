Troubleshooting

The reader is not found

SignCause and remedy
Message No Reader Found, status UNKNOWNCheck the cable and the port. Open Tools > Settings..., choose the provider (Elatec TWN4 or PCSC) and click Connect, with a chip on the reader. With PCSC the reader has to be listed under Detected PC/SC Readers; if not, check the "Smart Card" service of Windows.
(port not accessible) with an Elatec TWN4Another program or a second RFiDGear window holds the port of the reader. Close it and click Connect again.
RDP: PC/SC unavailable, PCSC cannot be selectedYou are working in a Remote Desktop session. Switch on smart card redirection of the connection (redirectsmartcards:i:1 in the .rdp file or in the settings of the Remote Desktop client); the reader must be attached to the local computer.
The status stays INITRFiDGear is still looking for the reader. If it takes long, check the same points as above.
A card is not recognized at allCheck the position of the card on the reader. With an Elatec TWN4, RFiDGear searches for all high-frequency card types except HID iCLASS; an iCLASS card stays invisible.
A MIFARE SAM AV3 is not foundA TWN4 sees it only from hardware revision G (see Setting up a MIFARE SAM AV3). The setup window looks at all PC/SC readers by itself and does not use the setting SAM reader:; that setting matters only when a task uses a key of the SAM.

A task fails

The result of the task names the cause. All results are on the page Tasks at a glance. The most common:

ResultWhat to do
Authentication FailedThe card refuses the key. Check the key and the type (DES, AES, ...). With MIFARE Classic a chip halts the card after a refusal: the next command fails once. Take the card away, put it on again and run the task again.
Permission DeniedThe access rights of the card forbid the operation with this key.
Protocol ConstraintThe reader or the card cannot do that. An Ultralight EV1 or an NTAG, for example, can be read and written only with an Elatec TWN4, not with a PC/SC reader.
Transport ErrorThe connection broke: card removed too early, reader unplugged. Put the card on again. A task that was writing may have written in part; check the card before you repeat.
Key unavailableA key that the task names by a reference could not be had from its key store. No command went to the card for it. A failure of a SAM is another case. See Keys.
Card not expectedThe card on the reader is not the one the caller expects, or the variable $EXPECTEDUID has no value.
Is Not TrueA check said "no". That is an answer, not a defect.

Other cases

  • The task list cannot be changed. A run, the loading of a project or another change is in progress. Wait until the status shows IDLE.
  • A report is not made. The PDF template has to exist and have form fields, and the folder of the target path has to exist. See Reports.
  • A project cannot be opened. The file has to be an .rfPrj archive or an .xml project file. The log names the reason.
  • The help does not open. The setup puts RFiDGear_de.chm and RFiDGear_en.chm next to RFiDGear.exe. If the file is missing, RFiDGear says so. If the help shows blank pages, Windows has blocked the file because it came from the network or a download: open its properties and choose Unblock (or copy RFiDGear to a local drive).
  • An extension is missing. RFiDGear finds extensions only at start; restart it. See Updates and extensions.

The log

RFiDGear writes a log to %LocalAppData%\RFiDGear\log\. The files roll and are kept for 30 days. The log names errors and their cause; RFiDGear deliberately writes no keys into it.

Questions and bug reports

The project has its page on GitHub: https://github.com/c3rebro/RFiDGear. There you can report bugs and look for versions. Attach an excerpt of the log and the version from Help > About RFiDGear. Remove everything first that you do not want to pass on.

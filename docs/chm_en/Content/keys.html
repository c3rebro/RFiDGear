Keys

Every card key of a task is given in one of two ways:

  • Typed: you enter the hex digits in the task. The key is then in the project file.
  • As a reference: the task names only the name of a key in a key store. The project saves the name, never the key; RFiDGear fetches the key only when the task runs.

With references a project can be passed on without giving keys away. It then runs on another computer or for another Windows user only when the same keys are stored there under the same names. Versions of RFiDGear that do not know references cannot run such a project.

The key stores

Key storeWhat it is
Windows Credential Managerthe vault of Windows for this user of this PC. RFiDGear keeps its keys there under the name RFiDGear/key/<name>.
Connected external applicationa program that is connected to RFiDGear through external control and supplies the key when the task runs. The project saves only the name; the program decides what it means. If external control is not running, or no program has registered as the supplier, the task ends with Key unavailable.
MIFARE SAM AV3the key stays in a SAM and never reaches RFiDGear. The reference is a key entry with a version, for example 3:0 (entry 1 to 127). See Setting up a MIFARE SAM AV3.
Store of an extensionan installed extension can bring a key store of its own (see Part 2 of this help)

Set a key in a task

Next to each key field is a switch, and below the key fields of a section is the button Key manager.... It opens the window Key manager for the keys of that section. There you say for each key where it comes from:

Button, fieldEffect
Use the typed keythe key is typed into the task (and is in the project)
Use a referencethe key comes from a key store. Choose the Key store and then the Stored key from the list. For a SAM you enter Key entry and version.
Create a new key: Name of the key, key field, Store keystores a new key in the Credential Manager and uses it for this key at once. A name that is already in use is never overwritten; if RFiDGear cannot read the list, it stores nothing.
Show keyshows the digits while you type, so that you can check them. The field is green when the key has the right length and red when not. It is cleared as soon as the key has been used.

A key field that points to a reference is gray and shows the reference instead of the key. A task with a reference never uses the typed key, even if the reference is broken.

Manage stored keys

File > Key manager... needs no project. The window lists the stored keys by name only (no key is read to show the list).

FieldEffect
Stored keysthe list; Remove deletes the selected key from the Credential Manager, after a question. Projects and tasks that name it can no longer get it; that cannot be undone.
Store a keya new key with Name of the key and the Kind of key: MIFARE Classic key (12 digits), DES, 2K3DES or AES key (32 digits) or 3K3DES key (48 digits)

Move the keys of an existing project

File > Move keys of a project to the Credential Manager... takes the typed keys of a project, puts them in the Credential Manager and saves a new project that refers to them. You first choose the project (Project whose keys are to be moved) and then the name of the new one (Save the new project as). The original project is only read, never changed. At the end RFiDGear asks whether the original project is to be deleted; before that it reads the new one once more and fetches every key it refers to. With No it is kept.

When a key cannot be had

If a key cannot be fetched from a key store (it is missing from the Credential Manager, no program supplies it), the task ends with Key unavailable before a command goes to the card. The status message says: The key for ... is not available; nothing was sent to the card. A task that waits for a refused authentication (Authentication Failed) is not started by it. A key of a SAM is another case: the SAM and the card work together, so a failure of the SAM can come after the card was addressed. The status line then names the reason and the status words of the SAM and of the card, and the task ends with the result of the step that failed.

A key that you type is in the project file in plain text, and the default keys in the Settings are in plain text in runtime-defaults.json. Use a reference for real keys.

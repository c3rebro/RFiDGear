External control: quick start

A program next to RFiDGear can drive the official process over one named pipe with JSON-RPC 2.0: load a project, run its tasks on a card, read the results and supply card keys. The reason it exists is a program that encodes cards in series; the interface is kept general.

1. Switch it on

RFiDGear listens only when you ask it to:

  • the setting Enable JSON-RPC pipe server (Tools > Settings..., tab Miscellaneous Settings); a change takes effect after a restart, or
  • the start-up argument EXTERNALCONTROL=1 for one run of RFiDGear (see Start-up arguments).

Either one is enough. While external control serves a program, the status bar shows External control: connected. One RFiDGear instance runs per Windows session; a second one exits at once, so a program connects to the one that runs or starts exactly one.

2. The pipe

  • Name: \\.\pipe\RFiDGear.Bridge.<SID>, where <SID> is the security identifier of the Windows user who runs RFiDGear (BridgeProtocol.PipeNameFor).
  • Only that user can open it. RFiDGear creates it with CurrentUserOnly; open it that way in the client too, so that you never talk to a pipe that somebody else made under that name.
  • One client at a time: a second one waits until the first has left.
  • Start RFiDGear and the client with the same rights (the effect of different elevation has not been tried).

3. What the client needs

  • RFiDGear.Bridge.Contracts.dll from the install folder (there is no package yet). It has no references, is net10.0 and keeps the assembly version 1.0.0.0.
  • StreamJsonRpc in the version that RFiDGear uses (2.26.150), or a compatible one.

4. Connect and hello

using var pipe = new NamedPipeClientStream(".", BridgeProtocol.PipeNameFor(sid), PipeDirection.InOut,
    PipeOptions.Asynchronous | PipeOptions.CurrentUserOnly);
await pipe.ConnectAsync(TimeSpan.FromSeconds(10));

var formatter = new SystemTextJsonFormatter { JsonSerializerOptions = BridgeJson.CreateClientOptions() };
var rpc = new ErrorDataRpc(new HeaderDelimitedMessageHandler(pipe, formatter));   // see below

var names = new JsonRpcTargetOptions { MethodNameTransform = CommonMethodNameTransforms.CamelCase };
rpc.AddLocalRpcTarget<IBridgeClientEvents>(events, names);
rpc.AddLocalRpcTarget<IBridgeClientKeys>(keys, names);
var service = rpc.Attach<IBridgeService>(new JsonRpcProxyOptions { MethodNameTransform = CommonMethodNameTransforms.CamelCase });
rpc.StartListening();

var hello = await service.Hello(new HelloRequest
{
    ClientName = "MyProgram", ClientVersion = "1.0",
    ProtocolMajorMin = BridgeProtocol.Major, ProtocolMajorMax = BridgeProtocol.Major,
    Events = new[] { "runCompleted" }
});

sid is the security identifier of the current Windows user (WindowsIdentity.GetCurrent().User.Value).

Important: derive from JsonRpc and override GetErrorDetailsDataType with return typeof(BridgeErrorData);. Without it the library reads error.data as its own type, the data of the interface (the kind, the error id, neverStarted) is lost, and you cannot tell a refusal from a doubt.

A method name of the contract is its camel-case name: hello, getStatus, startRun.

5. What to read from the answer to hello

  • The capabilities (capabilities): call only what is offered. A method whose capability is missing ends with capabilityNotSupported, never as a silent no-op.
  • The instanceId: the identifier of the RFiDGear process. If it changes between two connections, RFiDGear was restarted, the result numbers start again, and what you noted is not in it.
  • The limits (limits): keep inside them.
  • Until getStatus says startupComplete, everything but hello and getStatus answers notReady: wait and ask again.

6. Try it

Start RFiDGear with EXTERNALCONTROL=1 and then RFiDGear.Bridge.SampleClient status. The sample client (see The sample client) does everything on this page and more.

A run writes to cards. Try external control first with a project that only reads, and on a card you no longer need.

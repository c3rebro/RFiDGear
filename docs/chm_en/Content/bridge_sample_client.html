The sample client

RFiDGear.Bridge.SampleClient is a small client of external control, to read and to try. It is net10.0, references only RFiDGear.Bridge.Contracts and StreamJsonRpc, and does what the guide asks for. Its tests (BridgeSampleClientTests) are the proof that the advice in this part of the help works.

The commands

Start RFiDGear with the setting for external control or with EXTERNALCONTROL=1. Then:

CommandEffect
statusshows what getStatus says
run <requestId> <project.rfPrj> $JOBNUMBER=4711loads a project, notes its state and runs it. It prints the request id before it calls, so that you can ask about the run even if the program is killed on the way. A result that cannot be told is printed as Unknown with the advice to look at the card first; the exit code is then not zero. --expect-revision=<revision> passes a revision that you noted from status
result <requestId>asks what became of a request
results <number>lists what a client missed
approved-run <requestId> <project.rfPrj>the flow for one card: loads, notes the revision, looks at the reader, shows the UID and asks you to type yes, starts one run with the UID in $EXPECTEDUID (--variable=$NAME for another name; --yes answers for you, for a test), and then compares the card of the result with the approved one. The exit code is 0 only for a confirmed run
autoswitches the plain automatic mode on until you press Ctrl + C
auto --approve-with=$EXPECTEDUID [--no-pin] [--wait=8] [--set=NAME=value]the mode with approval: every card is approved by one fixed rule. --decline declines every card, --no-answer never answers: so that you can see each end by hand
keys orders/4711 --own-runs-only --run=job-2serves a key for one reference (typed at a prompt that does not show it); --own-runs-only asks RFiDGear to answer for every run that the sample did not start and checks it again itself; --run=<id> starts a run on the same connection, because the interface serves one client at a time
run and approved-run write to a card: use a test card.

The parts

ClassWhat for
BridgeSampleClientthe pipe of the current user (with CurrentUserOnly), the error data made readable, the handshake and the check of the capabilities, RunOnceAsync (starts a run and never repeats it as a new request), ResumeAsync (the way back after a lost connection or a restart), CatchUpAsync and KeyVault, the hook for your own vault
ApprovalModeLoopthe loop of a program that decides about every card in automatic mode: switch the mode on with requireApproval, hand every card to your decision (ApproveWith with the variables of the card, or Decline), answer with the presenceId, treat a decision that throws as a refusal, drop a decision whose card is given up meanwhile, and stop the mode only if it switched it on itself
ApprovalPolicythe fixed rules of the commands auto --approve-with, --decline and --no-answer
SampleVaulta vault that answers one reference and refuses all others: that is the shape every vault should have

The vault is not on the command line on purpose: a key does not belong in an argument.

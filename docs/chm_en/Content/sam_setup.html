Setting up a MIFARE SAM AV3

A MIFARE SAM AV3 is a security module that keeps card keys inside itself: RFiDGear never sees the key but has the SAM open a DESFire card with it or change its keys. This window sets up a SAM for that. It needs no project and opens with Tools > MIFARE SAM AV3 setup....

Prerequisites

  • The SAM sits in a PC/SC reader (with a reader pair such as the OMNIKEY 5422 in the contact slot, the card in the other slot) or in a SAM socket of an Elatec TWN4. A TWN4 sees a SAM AV3 only from hardware revision G (TWN4 MultiTech 2, two SAM sockets); older revisions never see it.
  • With a TWN4 the Elatec reader must be selected and connected in the settings. With a PC/SC reader finding the SAM is enough for setting it up; to use the SAM in tasks later, choose its reader under SAM reader: in the Settings.
  • While the window is open, it has the reader to itself. If a run or another window holds the reader, it does not open.

The steps

StepButtonWhat happens
1. Find(on opening) Search againRFiDGear reads the answer to reset (ATR) of each card in each reader and socket and lists the SAMs under SAM in reader. It connects to no card while doing so. If it finds none, No MIFARE SAM AV3 found. is shown.
2. CheckCheck SAMconnects to the SAM and asks for its version. No key is used and nothing is changed. The window shows Hardware information and software information.
3. ActivateActivate SAM...only for a new SAM that says "not activated". RFiDGear asks first; No is the default.
4. AuthenticateAuthenticatelogs you in as host with the Master key (key entry 0, version 0). The key is the Factory key (sixteen zero bytes, for a new SAM), a Stored key from the Credential Manager or a typed key.
5. Write a keyWrite keywrites a PICC key into a Key entry (1 to 127) as version 0. The Key type: is AES-128 (DESFire) for a card with an AES key or DES / 2K3DES (DESFire native) for a card with the old key type. The key has 32 hexadecimal digits.

The field Messages shows what happened. Every step is tried exactly once and never repeated.

Activating is final. It worked on the one SAM AV3 it was tried on, and that SAM stayed activated even after it was taken out and put back. No way back is known. Do it only for a new SAM that you want to use, with its master key. A wrong key when authenticating counts as a use of the key if a usage counter is linked to the entry.

After writing

RFiDGear reads the key entry back and checks that it is enabled, has the right type and belongs to the PICC class. A blank entry is disabled (SET bit 9) until a write enables it: if the window says key entry ... is disabled, write the key again. The key itself can never be read back; a SAM never gives a key out.

Using the SAM in tasks

In a key field of a DESFire task choose MIFARE SAM AV3 as the key store and give Key entry and version, for example 3:0 (see Keys). Four commands can do that: Check: App Key, Change PICC Master Key, Change Application Key and the button Authenticate with PICC MasterKey (see MIFARE DESFire). When a key is changed, all keys of the command must come from the SAM, because the SAM forms the encryption of the change from the old and the new key.

With a PC/SC reader RFiDGear uses the reader that the setting SAM reader: names. With a TWN4 it finds the SAM by itself; if SAMs sit in both sockets, it takes neither (the keys of the two are not the same): remove one.

The window has not yet been clicked through with a real SAM. The key changes themselves have been played through with a TWN4 and a DESFire test card without data; nothing has run through the window of the task yet.

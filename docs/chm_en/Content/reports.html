Reports (PDF)

A report records what happened to a chip in a run. For that RFiDGear fills the form fields of a PDF template and saves the result as a new PDF file. You add the report as a task: Edit > Add / Edit Task(s) > Add / Edit Generic (Non-Chip) Task..., task type Create / Edit Report (the page Generic tasks describes the fields of the dialog).

How a report comes about

  1. You need a PDF template with form fields. Every field has a name; a PDF editor with form functions creates such fields.
  2. In the dialog you open the template with Open File.... The names of its fields then appear in the selection Template Field.
  3. For each field that you want to fill, you add a checkpoint: the field, the content, the task it refers to, and the result that task has to have.
  4. In the task list the report stands below the tasks whose result it records, because it reads their results when it runs.

In a run RFiDGear writes every checkpoint whose target task has the expected result into its field. A checkpoint whose target task had another result is ignored. So a report can enter "passed" or "not passed", depending on the outcome of a check: two checkpoints for the same field, one for No Error, one for Is Not True.

A checkpoint whose target task does not exist (any more: you deleted or renumbered it) writes nothing, and the log names the missing task number (never the content). A checkpoint without a target task is a plain field (a date, a UID, a fixed text) and is always written. After you delete or renumber tasks, check the targets of the report.

Variables in the content of a checkpoint

The Fieldvalue may contain placeholders that are replaced in the run:

Placeholderis replaced by
%UIDthe UID of the chip
%CHIPTYPEthe chip type
%SLAVEUID, %SLAVECHIPTYPEUID and type of the second chip of a multi-technology card
%DATEthe date, DD/MM/YYYY
%DATETIMEdate and time in the notation of your Windows
%FREEMEMthe free memory of a DESFire card in bytes
%LISTAPPS, %COUNTAPPSthe application IDs of a DESFire card, separated by commas, and their number
%n, %nn, %nnna running counter with one, two or three digits (1, 01, 001). It starts at 1 with every program start and rises by 1 with every use
$NAMEthe value of a variable of the run, for example from a start-up argument (see Start-up arguments)
%NEWLINEa line break; the content is appended
%CONCATappends the content to the field instead of replacing it

If the content contains $NAME, %NEWLINE or %CONCAT, it is appended to what the field held before; otherwise it replaces it. A text that is not a placeholder is written as it stands, so it shows in the report.

Where the report is written

  • If the variable REPORTTARGETPATH (also REPORTOUTPUTPATH) is set, RFiDGear saves the report under that path. The folder has to exist. A ?, ?? or ??? in the file name stands for the next free number in that folder, with one, two or three digits: C:\Reports\report-???.pdf becomes report-001.pdf if no such file exists yet. The number is chosen for each run: the window and automatic mode give every card its own file, and what stands before and after the question marks (card-???-result.pdf) is matched as well. A path without question marks is the same file for every run.
  • The variable REPORTTEMPLATEFILE (also REPORTTEMPLATEPATH) chooses another template than the one in the dialog, if the file exists.
  • Without REPORTTARGETPATH, RFiDGear asks for the file name in the run with the window Save Report as.... RFiDGear remembers the path that you choose there for the following runs: every run writes to the same file until you forget the path (and the pattern of a start-up argument) with Edit > Reset Report Target Paths.

You give the variables as start-up arguments, or another program supplies them with the run. The page Start-up arguments shows examples.

For a series of cards, automatic mode included, put a ? into REPORTTARGETPATH: every run gets its own file. A fixed path, or a path that you chose in the window, is the same file for every run, and the next card overwrites the report of the one before. Each run starts its report from the template, so no field keeps the value of the card before; only a run of the selected task alone goes on with the report as it is. A program that asks for the runs can name the target for each run (Part 2 of this help).

Running tasks

Start a run

WhatHow
the whole list onceProgramming > Run All Tasks On Selected Chip Just Once (Ctrl + X), or Run All Tasks in the context menu
one task onlyselect the row and choose Programming > Run Selected Task on Chip Just Once, or Run Task in the context menu of the row
automatically for each new cardProgramming > Run All Tasks Automatically (see below)
at program startthe start-up argument AUTORUN=1 (see Start-up arguments)

Only one run goes on at a time. While one works, the status bar shows BUSY, and RFiDGear does not accept a second one.

What a run does

  1. In a run of the whole list RFiDGear first resets all results. A run of the selected task only leaves the other results as they are.
  2. RFiDGear reads the chip on the reader and remembers its UID.
  3. It runs the tasks from top to bottom. A task with an execute condition runs only if the earlier task had the result that is asked for; otherwise it is skipped (see Tasks at a glance).
  4. Each task shows its result at the start of its row: tick or cross.

Do not remove the card while a run works. A task that fails on a removed card ends with Transport Error. RFiDGear never repeats write tasks on its own: what they wrote in part stays on the card, and the result says where they failed.

Reset results

The results stay after a run until you reset them or the next run of the whole list begins. Reset them by hand with Edit > Set Taskstatus to 'Undone' or, for one task, with Reset Task in the context menu; Reset All Tasks does it for all, Run All Tasks resets and then starts the run.

When a run has succeeded

A program that asks for a run (external control, an extension, AUTORUN) gets one of three answers as the result:

ResultWhen
succeededevery task that ran ended with No Error, and all tasks were reached
succeeded, with intended failuresa check said "no" (Is Not True), or a task failed and a later task caught that with an execute condition
faileda task failed and no later task reacted to it; a program start failed; Card not expected occurred; or the run ended before all tasks were reached

A task that was skipped because of its execute condition is not an error.

Quick check

Programming > Perform Quick Check (Ctrl + Q) or the entry QuickCheck in the chip tree reads a chip without your having to add tasks:

  • With MIFARE Classic it tries to read all data blocks of the card with the default keys and shows the result, with the sector trailers, in the tree. The keys come from the Settings (tab Default Keys), after a question depending on the setting.
  • With MIFARE DESFire it lists the applications that are present and tries to collect their key settings.

Automatic mode

With Programming > Run All Tasks Automatically RFiDGear works through a series of cards: you put a card on the reader, the list runs once, you take the card away and put the next one on. AUTOMODE=1 at start switches it on, too.

  • Each card runs once per placing. If a card stays on the reader, it does not run again. Only when the reader was empty and a card (even the same one) is placed again does a new run begin.
  • A run that fails is never repeated. A card that you ran by hand counts as processed.
  • The mode stops when something unusual happens: a fault in the program, a task that does not finish, a lost reader. An ordinary failure of a task does not stop it. Switch it on again deliberately afterwards.
  • Another program that starts the mode through external control can have each card shown to it first and released by it (Part 2 of this help).
The entry Run Selected Task Automatically has no function.

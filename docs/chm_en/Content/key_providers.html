Writing a key provider

A key provider supplies card keys that a project names by a reference instead of containing them. As an extension you write it against ISecureKeyProvider from RFiDGear.Contracts and export it with [SecureKeyProvider("id", "Display name")] from RFiDGear.ExtensionSdk. (A program that connects to RFiDGear supplies keys through external control instead: see Keys through external control.)

How RFiDGear uses providers

  • DESFire, MIFARE Classic and Ultralight tasks ask the providers for the keys of their bound slots, all of them before the first command to the card, each once per task run. A slot is bound by an entry in the project file (slot, provider id, reference). In the task dialogs the button of the key manager binds it.
  • SecureKeyRegistry is the only way to call a provider. It creates each provider once, calls it from worker threads under a time limit, turns anything a provider does wrong into a failed answer, logs only the type of a provider's exception (never the message) and disposes a key that arrives late.
  • If a key cannot be had, the task ends before the card is touched (KeyUnavailable). For a MIFARE Classic task it is all or none: the reader never goes on with key A alone.
  • The built-in provider is windows-credential-manager (it reads a key from a generic credential with the prefix RFiDGear/key/); no extension can take over its id. Also built in: bridge-client and sam (a reference to a key entry of a MIFARE SAM AV3, without key bytes).

The rules for a provider

ItemRule
Id1 to 64 of a-z, 0-9, ., _ and -. It is stored in project files and never changes. Another id is ignored with a log entry; if two extensions use one id, neither is used.
Referenceopaque to RFiDGear except for its shape: 1 to 128 of A-Z, a-z, 0-9, ., _, :, / and -. A binding with another shape fails before any call. What it means is up to the provider.
Creationone instance per provider, on the user-interface thread, when the host builds its registry: the constructor must be quick and must not show anything or wait.
Threadsthe host calls from worker threads, possibly several at once, never with a synchronization context. Be thread-safe.
Answera new SecureKeyLease for every call. The host owns it and disposes it; it is pinned memory that is zeroed on dispose. Do not keep copies. ToHexString() makes a string that nobody can zero.
Same requestthe same key within one run (RunId). Rotate keys between runs, never in the middle of one.
Failurefailure is an answer: SecureKeyResolution.Failed(reason). A provider that throws counts as ProviderUnavailable. Write your own diagnostics and keep keys out of them.
Timehonor the cancellation token: the host waits 10 seconds (5 minutes for an Interactive request) and disposes a key that arrives late. A request with Interactive = false must not show a prompt.
Unknown algorithmanswer Unsupported. The host checks the length of every answer and ends the task with KeyUnavailable when it does not fit.

The slots and algorithms

TaskRequest
MIFARE ClassicAlgorithm is Classic6Byte (6 bytes); the scope has neither an application nor a key number; Usage is Authenticate for keys that open a sector and ChangeKeyNew for the ones written into a sector trailer. The sector is not part of the request, because one MAD operation uses a key for several sectors.
Ultralight Cslot ultralight.c.key, TripleDes2K (16 bytes), Usage Authenticate
Ultralight EV1 and NTAGslot ultralight.password (UltralightPassword, 4 bytes) and ultralight.pack (UltralightPack, 2 bytes)
DESFirethe keys of the PICC and of an application; a slot that is bound to the SAM is no key and has no bytes
An extension runs inside RFiDGear with the rights of the user and can read whatever the application can. A provider is not a security boundary. Install only providers you trust.

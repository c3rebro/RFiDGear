Files and folders

Where RFiDGear keeps something, and what is in it.

The folders

PlaceContent
%LocalAppData%\RFiDGear\settings.xmlthe settings (XML), also the default keys of the settings window in plain text
%LocalAppData%\RFiDGear\runtime-defaults.jsonthe first values at the first start: reader choice, language, COM ports, default keys for MIFARE, behavior of the update. The settings window saves to settings.xml
%LocalAppData%\RFiDGear\log\the log (Serilog, rolling files, 30 days). Errors go only there, not to the Windows event log
%LocalAppData%\RFiDGear\bridge\the journal of external control: a run is written down there before it begins, so that after a restart the admitted request ids are still known
%LocalAppData%\RFiDGear\report-work\<runId>the work folder of a report that the approval of a card triggers; it is removed after the run
%LocalAppData%\RFiDGear\InstalledExtensions\<id>\<version>the extensions that the user installed as a package (see Extension packages)
%ProgramData%\RFiDGear\Extensions\the extensions for all users; a normal user cannot write there
the folder of RFiDGear.exethe program, RFiDGear.Bridge.Contracts.dll for clients of external control and the help (RFiDGear_de.chm, RFiDGear_en.chm)
Windows Credential Manager, names under RFiDGear/key/the stored card keys (see Keys)

Project files

  • .rfPrj: a zip archive with the tasks as versioned XML. RFiDGear writes a project straight into its archive; no plain copy with typed keys stays in %LocalAppData%.
  • .xml: a project as a plain XML file.
  • The revision of a project (external control) is a hash of the text that a save would write, with a key that RFiDGear makes at start and never writes: a typed key cannot be found out from it, and it is valid for one process only.

What to know when you change something

  • Creating a DatabaseReaderWriter deletes files in the root folder of its project manager. Moving the keys of a project therefore runs on a project manager of its own.
  • No log line of RFiDGear holds a key, a reference, a reader name, the serial number of a SAM or the text of an exception of the SAM library. The own trace of LibLogicalAccess (config.log.enabled with seecommunication) would write the whole answer: leave it off while a SAM is in a reader.
  • The file hil.settings.json of the hardware tests sits next to Run-HilTests.bat and is not in git.

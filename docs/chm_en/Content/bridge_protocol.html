The protocol

The pipe speaks JSON-RPC 2.0 (StreamJsonRpc, HeaderDelimitedMessageHandler with Content-Length headers), UTF-8 JSON.

The form of the messages

  • The parameters are positional with exactly one object: the request type of the method.
  • The names are camel case and are written explicitly in the contract (BridgeJson has the options). RFiDGear rejects members it does not know; a client skips members it does not know.
  • A message longer than 1 MiB ends the connection.
  • RFiDGear sends notifications one after the other. A client that does not take a notification within ten seconds (a send that takes longer) is disconnected, and so is one for which more than 64 durable notifications wait (results, changes of the mode, and the notices about a card that is shown). The results stay in the history; you catch up after you reconnect. An idle connection is not cut off.

Rules that hold for every call

  • hello comes first. Anything else before it ends with handshakeRequired.
  • A method whose capability this RFiDGear does not offer ends with capabilityNotSupported. A client decides what it may call from the capabilities in the answer to hello, never from the version of the application.
  • Until RFiDGear has finished starting, everything but hello and getStatus ends with notReady.
  • RFiDGear never repeats a card operation, and a client must not either (see Requesting runs safely).

Every method and every event has exactly one capability; the answer to hello is generated from those statements, so a capability cannot be offered without its method. A new field in a request ships only with a new capability that a client has seen.

Errors

An error is a JSON-RPC error with an application code; error.data holds kind, an optional errorId (it also appears in the log of RFiDGear), neverStarted and details. The text of the error is never an exception message. An unknown method and a request that does not fit reach a client as -32601 and -32602.

Limits

Also in hello: 1 MiB per message, 64 variables, 128 characters per name, 2048 per value, 4096 per path, 64 results and 1024 request ids kept, 30 seconds of waiting per getRunResult, 32 bytes per key.

Versioning

The protocol has a major version (1 today), which the client names in hello as a range. Within the major version nothing is removed or re-meant once the protocol is frozen; a client reads what a newer RFiDGear adds as optional. The assembly version of the contract stays 1.0.0.0.

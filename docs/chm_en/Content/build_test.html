Building and testing

Prerequisites

  • Everything targets .NET 10: the host, the test projects, the sample plugin, the contracts and the Card Check Assistant as net10.0-windows, the sample client and the CardCheck library as net10.0. global.json pins the SDK to 10.0.x (a newer preview SDK on the machine would otherwise be picked up).
  • Visual Studio 2022 cannot target net10.0: use Visual Studio 2026 or the dotnet command line.
  • The project is a WPF program for Windows (x64 and x86).

Commands

dotnet build RFiDGear.sln -c Debug
dotnet build RFiDGear.sln -c Release

dotnet test RFiDGear.Tests/RFiDGear.Tests.csproj
dotnet test RFiDGear.Tests/RFiDGear.Tests.csproj --filter "FullyQualifiedName~MyClass.MyMethod"

The tests

  • RFiDGear.Tests are the unit and integration tests, without a reader. They run on xunit.v3 (the package xunit.v3.mtp-off; the .NET 10 SDK otherwise refuses to run a project that is built on Microsoft.Testing.Platform through the VSTest path of dotnet test). The test projects are therefore executables; dotnet test and --filter work as usual.
  • A test that touches WPF needs an STA thread (StaTestRunner.cs). A test that builds a main window passes a temporary journal folder and a unique pipe name.
  • Approved snapshots hold the public surface of the contracts (RFiDGear.Tests/ApiSurface/). A change fails the test; you accept it by regenerating the snapshot: RFIDGEAR_UPDATE_API_SNAPSHOT=1 and the filter BridgeContractsApiSurface (or ExtensionSdkApiSurface). A mutation run that changes the contracts has to have FullyQualifiedName~ApiSurface in its filter.
  • BridgeSamples and BridgeGolden hold one value of every message of external control and its JSON: a change of the wire is a difference in a test.
  • The tests of the help (HelpFilesTests, HelpFileTests) read the real files under docs.

Hardware tests

RFiDGear.HIL.Tests run against a real reader and real cards. They are not part of the normal test run; the solution only compiles them. Start them with Run-HilTests.bat; hil.settings.json next to it switches the cases on: readerScan, interactive, secureKeys, cardWrites and readerKind (auto, elatec or pcsc). The checklists are in EXTERNAL-CONTROL.md, CLASSIC.md, ULTRALIGHT.md, SECURE-KEYS.md, SAM-AV3.md and SAM-PICC.md. Cases with cardWrites write to cards: use cards you no longer need.

Extensions, help, installers

  • Trying extensions while you develop and making packages: see Writing an extension and Extension packages.
  • The help is built by docs/Build-Help.ps1 with hhc.exe of HTML Help Workshop; the compiled .chm files sit next to their sources in the repository, because a normal build (and every test) does not need HTML Help Workshop.
  • The installers (RFiDGearBundleSetup and the two MSI projects) use WiX 3.14 and are built separately, not with dotnet build: first the host and the sample plugin in Release for the platform, then the MSI projects, then the bundle, with the MSBuild of Visual Studio 2026. A release is made by RFiDGearBundleSetup\Build-Release.ps1, then Sign-Release.ps1 and Pack-Release.ps1 (Make-Release.bat runs the three). The version is written by hand in RFiDGear.csproj, Bundle.wxs and update.xml; a test stops a release in which they differ. The certificate is not in the repository (RFIDGEAR_SIGN_PFX, RFIDGEAR_SIGN_PASSWORD).

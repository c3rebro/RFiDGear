Start-up arguments

RFiDGear accepts arguments at start. With them you load a project, start a run from a script or from another program, and give the run values that change from card to card. Only one instance of RFiDGear runs at a time.

The form

An argument is NAME=value, with no spaces around the =. The name of the known arguments is not case-sensitive. A value may itself contain a =. If an argument contains spaces, put the whole argument in quotation marks.

The arguments

ArgumentEffect
C:\Path\Project.rfPrjloads this project. The argument is a path that ends in .rfPrj; the file must exist.
CUSTOMPROJECTFILE=pathas above, for a project file with another extension; the file must exist
LASTUSEDPROJECTPATH=pathsets the last used project of the settings (see Projects) and saves it
AUTORUN=1loads the project, resets the results, reads the card on the reader and runs all tasks once. It returns no result to the program that started RFiDGear. RFiDGear stays open afterwards, unless the project ends with a program task %EXIT (see Generic tasks).
AUTOMODE=1switches the automatic mode on (see Running tasks)
EXTERNALCONTROL=1opens external control for this run, even if it is switched off in the settings (see Part 2 of this help)
REPORTTARGETPATH=path, REPORTOUTPUTPATH=paththe file the report is written to. The folder must exist; a ?, ?? or ??? in the file name stands for the next free number, chosen for each run (see Reports)
REPORTTEMPLATEFILE=path, REPORTTEMPLATEPATH=paththe PDF template of the report, instead of the one set in the dialog. The file must exist.
$NAME=valuea variable of the run. Every argument whose name contains a $ is one. The tasks can read it: Check UID ($EXPECTEDUID), a report, a program task and a logic block.

The switches (AUTORUN, AUTOMODE, EXTERNALCONTROL) apply only with the value exactly 1.

Examples

Load a project and run it once, with the report in a numbered folder (command prompt):

RFiDGear.exe "C:\Projects\Delivery.rfPrj" AUTORUN=1 "REPORTTARGETPATH=C:\Reports\card-???.pdf"

Expect one particular card (PowerShell; the single quotation marks keep PowerShell from evaluating the $):

.\RFiDGear.exe "C:\Projects\Delivery.rfPrj" AUTORUN=1 '$EXPECTEDUID=04A1B2C3D4E5F6'

If another card is on the reader, the task Check UID ends with Card not expected, and the run has failed (see Chip tasks for any card).

Another program can supply the same variables without a start-up argument when it asks for a run through external control (Part 2 of this help). The project stays the same from card to card.

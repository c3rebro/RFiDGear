Chip tasks for any card

These tasks check the chip, whatever family it belongs to. Add them with Edit > Add / Edit Task(s) > Add / Edit Generic Chip Task...; the dialog opens only when a reader is connected. They are checks: they do not change the chip.

Task typeFieldChecks
Check UIDUIDwhether the UID of the card is the expected one
Check Type Of ChipIs Chip Of Typewhether the card is of this type
Check Tag Is MultiTag–whether the card carries more than one chip: besides the main chip a second one (the report variables %SLAVEUID and %SLAVECHIPTYPE name it)

Each task ends with No Error if the check holds and with Is Not True if not. A project can use the answer for branches with an execute condition (see Tasks at a glance). RFiDGear counts a "no" as the answer of the check, not as a fault of the run.

Check UID

The field UID holds one of two things:

  • A UID, for example 04A1B2C3D4E5F6. Upper and lower case do not matter, white space at the edges does not count. If the UID of the card matches, the task ends with No Error, otherwise with Is Not True. That is a question that the project can build on.
  • A variable, for example $EXPECTEDUID: the name of a variable of the run that is supplied by the program that asks for the run (a start-up argument, another program through external control or an extension). So one project serves every card of a series, and only the caller knows which card is due. A variable name starts with $ and has at most 64 letters, digits or underscores.

With a variable the task ends differently when something is wrong: if the variable has no value, an empty one or the UID of another card, the task ends with Card not expected. That is not a "no" answer but a refusal: a run that ends so has failed, even if a branch of the project reacts to it, and a branch for "another card" (condition Is Not True) is not taken for it.

The check compares the UID that the run read from the card at its start. It never uses what the reader may still hold of an earlier card.

Typical use: another program releases a card and starts the run with $EXPECTEDUID. The check alone stops nothing: make Check UID the first task and give every task that touches the card an execute condition on it (the Check UID task, result No Error). A task without that condition runs whatever the check said, and the run ends as failed only afterwards. See Start-up arguments and Part 2 of this help.

Check Type Of Chip

Choose a type from the list under Is Chip Of Type, for example Mifare Desfire EV1. The task ends with No Error if the card on the reader is of this type.

MIFARE Classic

Add the task with Edit > Add / Edit Task(s) > Mifare > Add/Edit Mifare Classic Task. It reads and writes the sectors of a MIFARE Classic chip (1K, 4K and related ones). The dialog opens only when a reader is connected.

The task types

Task typeEffect
Read Datareads the sector with the keys of the dialog; the data appear in the Data Explorer under Data on Chip
Write Datawrites the data of the memory into the data blocks of the sector
Edit Sectortrailer and Keyswrites new keys and new access bits into the sector trailer of the sector
Sector Unused Checkchecks whether the sector is unused

The tabs

Mifare Classic Keys

FieldMeaning
Sector Nr.the sector the task refers to
SectorKey - Currentthe A Key and the B Key that open the sector now: 12 hex characters each
SectorKey - Targetthe keys that the task type Edit Sectortrailer and Keys writes into the sector
Use MADthe task finds the sector through the MAD directory of the card instead of the sector number; the field Size (Bytes) gives the size of the application data. Use MAD Authentication opens the card with the MAD key.
MAD Key - Current, MAD Key - Targetthe keys for the MAD directory

Each key field can be switched: instead of the typed key it can point to a key in the Credential Manager (see Keys).

Sector Trailer Editor

The tab appears while the MAD is not used. Under Sector Trailer | Access Bits it shows a table of the access conditions of a sector. The columns Read Key A, Write Key A, Read Access Bits, Write Access Bits, Read Key B and Write Key B say which key may do what. You choose a row; RFiDGear works out the three bytes of the access bits, with their inverses, by itself.

Data Explorer

Two tables: Data on Chip (what was read last) and Data In Memory/File (what you want to write). The buttons Read Data and Write Data carry out the action at once on the card on the reader, not as part of a run; Load Data from Disk... loads data from a file into the memory.

What RFiDGear observes when writing

  • One attempt. Every write is made once, read back and never repeated. The first block that fails ends the task. A block that does not read back as written ends as Unknown Error.
  • Data blocks. Write Data writes data blocks only: 32 bytes in sector 0, 48 bytes in a sector with four blocks, 240 bytes in one of the large sectors (sectors 32 to 39 of a 4K chip). RFiDGear never writes block 0 with the manufacturer data.
  • Sector trailer. It is written only by the task type Edit Sectortrailer and Keys and the Sector Trailer Editor. RFiDGear rejects access bits that are not consistent in themselves before it sends a key to the card.
  • Key B can be data. In the delivery configuration (access bits FF078069) key A may read key B: B is then a data area and cannot log in.
  • After a refusal the card halts. If a chip refuses an access, it halts the card: the next command fails once. RFiDGear wakes the card afterwards; the failure still stays a failure of the task.

The result names what failed: only Authentication Failed means that a key was refused; another error stays another error.

Wrong access bits can lock a sector for good. Try Edit Sectortrailer and Keys on a card you no longer need first. Write down the new keys before you write.
With a PC/SC reader only reading has been tried on a 4K card so far. Writing, the MAD and the dialogs are checked only against a chip simulated in memory, and with an Elatec TWN4 on no card at all. Check the result of every write task on a test card before you use it for a series.

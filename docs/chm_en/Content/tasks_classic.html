MIFARE Classic

Add the task with Edit > Add / Edit Task(s) > Mifare > Add/Edit Mifare Classic Task. It reads and writes blocks and sectors of a MIFARE Classic chip (1K, 4K and related ones). The dialog opens only when a reader is connected.

The task types

Task typeEffect
Read Datareads the sector with the keys of the dialog (with Use MAD the application through the MAD directory); the data appear in the Data Explorer under Data on Chip
Write Datawrites data of the memory to the chip. What is written depends on Use MAD: see "What Write Data writes" below
Sector Unused Checkchecks whether the sector is unused

The keys and the access bits of a sector are in the sector trailer, the last block of the sector. There is no task type of its own for it: you write the sector trailer like any other block with Write Data.

The tabs

Use MADthe task finds the sector through the MAD directory of the card instead of the sector number; the field Size (Bytes) gives the size of the application data. Use MAD Authentication opens the card with the MAD key.
MAD Key - Current, MAD Key - Targetthe keys for the MAD directory

Like those of other tasks, the key fields can be switched: instead of the typed key a field can point to a key in the Credential Manager (see Keys).

Sector Trailer Editor

The tab appears while the MAD is not used. Under Sector Trailer | Access Bits it shows a table of the access conditions of a sector. The columns Read Key A, Write Key A, Read Access Bits, Write Access Bits, Read Key B and Write Key B say which key may do what. You choose a row; RFiDGear works out the three bytes of the access bits, with their inverses, by itself.

Data Explorer

Two tables: Data on Chip (what was read last) and Data In Memory/File (what you want to write). In the selection you choose the block that Write Data writes without the MAD: Block 0, Block 1, Block 2 of the sector or the Sector Trailer. The buttons Read Data and Write Data carry out the action at once on the card on the reader, not as part of a run; Load Data from Disk... loads data from a file into the memory.

What Write Data writes

SettingWhat is written
without Use MADone block of 16 bytes: the block of the sector (from the sector number) that is chosen in the Data Explorer. If you choose the Sector Trailer, that changes the keys and the access bits of the sector: the block is written just as it stands in the memory. This works for sectors 0 to 31 only. In the large sectors 32 to 39 the selection Sector Trailer names the fourth block of the sector, which is a data block: it overwrites data and leaves the keys as they are. RFiDGear never writes block 0 of the chip with the manufacturer data.
with Use MADthe application data through the MAD directory. The sectors that the data reaches get the new keys and access bits as well (SectorKey - Target and the access bits that are set); if the card has no directory, RFiDGear creates one. The data come before the directory, the directory before the sector trailers.
  • One attempt. Every write is made once, read back and never repeated. The first block that fails ends the task. A block that does not read back as written ends as Unknown Error.
  • Checks before the card is touched. RFiDGear rejects access bits that are not consistent in themselves and a block that does not have 16 bytes before it sends a key to the card.
  • Key B can be data. In the delivery configuration (access bits FF078069) key A may read key B: B is then a data area and cannot log in.
  • After a refusal the card halts. If a chip refuses an access, it halts the card: the next command fails once. RFiDGear wakes the card afterwards; the failure still stays a failure of the task.

The result names what failed: only Authentication Failed means that a key was refused; another error stays another error.

Wrong access bits can lock a sector for good, and with the sector trailer you change its keys. Try that on a card you no longer need first. Write down the new keys before you write.
With a PC/SC reader only reading has been tried on a 4K card so far. Writing, the MAD and the dialogs are checked only against a chip simulated in memory, and with an Elatec TWN4 on no card at all. Check the result of every write task on a test card before you use it for a series.

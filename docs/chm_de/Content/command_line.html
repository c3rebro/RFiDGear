Startargumente

RFiDGear nimmt Argumente beim Start an. Damit laden Sie ein Projekt, starten einen Lauf von einem Skript oder einem anderen Programm aus und geben dem Lauf Werte mit, die von Karte zu Karte wechseln. Es läuft immer nur eine Instanz von RFiDGear.

Die Form

Ein Argument ist NAME=Wert, ohne Leerzeichen um das =. Der Name der bekannten Argumente gilt unabhängig von der Groß- und Kleinschreibung. Ein Wert darf selbst ein = enthalten. Enthält ein Argument Leerzeichen, setzen Sie das ganze Argument in Anführungszeichen.

Die Argumente

ArgumentWirkung
C:\Pfad\Projekt.rfPrjlädt dieses Projekt. Das Argument ist ein Pfad, der auf .rfPrj endet; die Datei muss existieren.
CUSTOMPROJECTFILE=Pfadwie oben, für eine Projektdatei mit einer anderen Endung; die Datei muss existieren
LASTUSEDPROJECTPATH=Pfadsetzt das zuletzt verwendete Projekt der Einstellungen (siehe Projekte) und speichert es
AUTORUN=1lädt das Projekt, setzt die Ergebnisse zurück, liest die Karte auf dem Leser und führt alle Aufgaben einmal aus. Es gibt dem Programm, das RFiDGear gestartet hat, kein Ergebnis zurück. RFiDGear bleibt danach offen, es sei denn, das Projekt endet mit einer Programmaufgabe %EXIT (siehe Allgemeine Aufgaben).
AUTOMODE=1schaltet den automatischen Modus ein (siehe Aufgaben ausführen)
EXTERNALCONTROL=1öffnet die externe Steuerung für diesen Lauf, auch wenn sie in den Einstellungen ausgeschaltet ist (siehe Teil 2 dieser Hilfe)
REPORTTARGETPATH=Pfad, REPORTOUTPUTPATH=Pfaddie Datei, in die der Bericht geschrieben wird. Der Ordner muss existieren; ?, ?? oder ??? im Dateinamen steht für die nächste freie Nummer, die einmal beim Start gewählt und für spätere Läufe gemerkt wird (siehe Berichte)
REPORTTEMPLATEFILE=Pfad, REPORTTEMPLATEPATH=Pfaddie PDF-Vorlage des Berichts, statt der im Dialog eingestellten. Die Datei muss existieren.
$NAME=Werteine Variable des Laufs. Jedes Argument, dessen Name ein $ enthält, ist eine. Die Aufgaben können sie lesen: die Prüfung der UID ($EXPECTEDUID), ein Bericht, eine Programmaufgabe und ein Logikbaustein.

Die Schalter (AUTORUN, AUTOMODE, EXTERNALCONTROL) gelten nur mit dem Wert genau 1.

Beispiele

Ein Projekt laden und einmal ausführen, mit dem Bericht in einem durchnummerierten Ordner (Eingabeaufforderung):

RFiDGear.exe "C:\Projekte\Auslieferung.rfPrj" AUTORUN=1 "REPORTTARGETPATH=C:\Berichte\karte-???.pdf"

Eine Karte erwarten (PowerShell; die einfachen Anführungszeichen verhindern, dass PowerShell das $ auswertet):

.\RFiDGear.exe "C:\Projekte\Auslieferung.rfPrj" AUTORUN=1 '$EXPECTEDUID=04A1B2C3D4E5F6'

Liegt eine andere Karte auf dem Leser, endet die Aufgabe Prüfung der UID mit Karte nicht erwartet, und der Lauf ist fehlgeschlagen (siehe Typunabhängige Chip-Aufgaben).

Ein anderes Programm kann dieselben Variablen auch ohne Startargument mitgeben, wenn es einen Lauf über die externe Steuerung anfordert (Teil 2 dieser Hilfe). Das Projekt bleibt dabei von Karte zu Karte gleich.

MIFARE DESFire

Die Aufgabe legen Sie mit Bearbeiten > Aufgabe erstellen / bearbeiten > Mifare Aufgabe > Mifare Desfire Aufgabe hinzufügen/bearbeiten an. Der Dialog öffnet sich nur, wenn ein Leser verbunden ist. Eine Aufgabe führt einen Befehl an der Karte aus; der Aufgabentyp wählt ihn, und die Reiter des Dialogs halten die Einstellungen dafür.

Schlüssel, Verschlüsselung, Dateien

  • Schlüsseltypen: 3DES (DES / 2K3DES), 3K3DES und AES. Das Feld lässt nur so viele Hex-Zeichen zu, wie der Typ braucht.
  • Kommunikationsmodus einer Datei: Plain, MAC oder Encrypted.
  • Dateitypen: Standard Data File, Backup File, Value File, Linear Record File und Cyclic Record File.
  • Zugriffsrechte einer Datei: Key 0 bis Key 13, without Key (ohne Schlüssel) oder not Allowed (nie).
  • Key-Änderungsmodus einer Applikation: Keychange frozen (Schlüssel nicht mehr änderbar), Change Key using MK (nur mit dem Master Key) oder Change Key using KeyNo (mit einer Schlüsselnummer).

Prüfungen mit Vergleich

Die Aufgaben Prüfung: App Konfig und Prüfung: Dateieinstellungen lesen etwas von der Karte und vergleichen es mit dem, was Sie erwarten. Die Aufgabe endet mit Kein Fehler (BESTANDEN) oder mit einem Fehlerergebnis (NICHT BESTANDEN); das Statusfeld des Dialogs nennt den Unterschied.

  • App Konfig: Sie hängen die erwarteten Schlüsseleinstellungen an (PICC/App-MasterKey änderbar, Konfiguration ist änderbar, App/File ohne MasterKey anlegbar, Verzeichnis ohne MasterKey einsehbar) und wählen die Regel: Alle gewählten Einstellungen müssen gesetzt sein, Mindestens eine gewählte Einstellung muss gesetzt sein oder Exakte Übereinstimmung (einschließlich Key-Änderungsmodus).
  • Dateieinstellungen: Sie haken die Einstellungen an, die verglichen werden sollen (Dateityp, Kommunikationsmodus, Größe, Lesezugriff, Schreibzugriff, Lese-/Schreibzugriff, Recht zum Ändern der Zugriffsrechte). Eine Einstellung ohne Haken wird ignoriert. Die Größe vergleichen Sie mit gleich, mindestens oder höchstens. Geprüft werden Standard- und Backup-Datendateien; Wert- und Record-Dateien nicht.

Daten lesen und schreiben

Im Daten Editor stellen Sie die App-ID, die Dateinummer, den Leseschlüssel mit Nummer und Typ (die Nummer liegt zwischen 0 und 13) und für das Schreiben den Schreibschlüssel ein. Dazu kommen die Datenindex Startposition und die Zahl der Bytes (Schreibe n Byte(s)). Die Tabellen zeigen Daten - IST (auf der Karte) und Daten - SOLL (im Speicher). Mit Datendatei Öffnen... laden Sie Daten aus einer Datei, mit Lese-Daten speichern... wählen Sie die Datei, in die gelesene Daten gespeichert werden. Beim Lesen überschreiben gilt für diese Datei: ist es angehakt, schreibt jedes Lesen in die gewählte Datei; sonst hängt RFiDGear Datum und Uhrzeit an den Dateinamen an (zum Beispiel lesen_20261121_133700.bin), damit frühere Lesevorgänge erhalten bleiben. Vor Schreiben neu laden lädt die Datei erneut, bevor geschrieben wird.

Schlüssel für eine DESFire-Aufgabe

Ein Schlüsselfeld kann einen eingetippten Schlüssel haben oder auf einen gespeicherten Schlüssel zeigen. Die Schaltfläche Schlüsselverwaltung... im Abschnitt des Schlüssels öffnet die Verwaltung (siehe Schlüssel). Als Quelle stehen zur Wahl: die Windows-Anmeldeinformationsverwaltung, eine verbundene externe Anwendung und eine MIFARE SAM AV3. Mit einem Schlüssel der SAM bleibt der Schlüssel in der SAM; das funktioniert für vier Befehle: Prüfung: App-Key, PICC Master Key ändern, App Key ändern und die Schaltfläche Mit PICC MasterKey Authentifizieren. Ein Schlüssel, der sich aus einem Schlüsselspeicher nicht holen lässt, beendet die Aufgabe mit Schlüssel nicht verfügbar; an die Karte geht dann kein Befehl. Ein Fehler der SAM selbst wird mit Grund und den Statuswörtern von SAM und Karte gemeldet.

Die Aufgaben dieser Seite können eine Karte unbrauchbar machen: Karte Formatieren löscht alle Daten, nach einem gelungenen Wechsel des PICC Master Keys braucht jede weitere Authentifizierung den neuen Schlüssel: geht er verloren, lässt sich die Karte nicht mehr verwalten. Ein eingefrorener Key-Änderungsmodus (Keychange frozen) verhindert spätere Schlüsseländerungen. Notieren Sie die neuen Schlüssel, bevor Sie sie schreiben, und üben Sie an einer Karte, die Sie nicht mehr brauchen. RFiDGear wiederholt einen Schreibbefehl nie von selbst.

Schlüsselanbieter schreiben

Ein Schlüsselanbieter liefert Kartenschlüssel, die ein Projekt über eine Referenz nennt, statt sie zu enthalten. Als Erweiterung schreiben Sie ihn gegen ISecureKeyProvider aus RFiDGear.Contracts und exportieren ihn mit [SecureKeyProvider("id", "Anzeigename")] aus RFiDGear.ExtensionSdk. (Ein Programm, das sich mit RFiDGear verbindet, liefert Schlüssel stattdessen über die externe Steuerung: siehe Schlüssel über die externe Steuerung.)

Wie RFiDGear Anbieter verwendet

  • DESFire-, MIFARE-Classic- und Ultralight-Aufgaben fragen die Anbieter nach den Schlüsseln ihrer gebundenen Plätze, alle vor dem ersten Befehl an die Karte, je einmal je Aufgabenlauf. Ein Platz ist durch einen Eintrag in der Projektdatei gebunden (Platz, Anbieter-ID, Referenz). In den Aufgabendialogen bindet die Schaltfläche der Schlüsselverwaltung ihn.
  • SecureKeyRegistry ist der einzige Weg, einen Anbieter aufzurufen. Sie erzeugt jeden Anbieter einmal, ruft ihn von Arbeitsthreads unter einem Zeitlimit auf, macht aus allem, was ein Anbieter falsch macht, eine gescheiterte Antwort, protokolliert nur den Typ der Ausnahme eines Anbieters (nie die Meldung) und verwirft einen Schlüssel, der zu spät kommt.
  • Kann ein Schlüssel nicht beschafft werden, endet die Aufgabe, bevor die Karte berührt wird (KeyUnavailable). Bei einer MIFARE-Classic-Aufgabe gilt „alles oder nichts“: der Leser fährt nie mit Schlüssel A allein fort.
  • Der eingebaute Anbieter ist windows-credential-manager (er liest einen Schlüssel aus einer allgemeinen Anmeldeinformation mit dem Präfix RFiDGear/key/); keine Erweiterung kann seine ID übernehmen. Ebenfalls eingebaut: bridge-client und sam (eine Referenz auf einen Schlüsseleintrag einer MIFARE SAM AV3, ohne Schlüsselbytes).

Die Regeln für einen Anbieter

GegenstandRegel
ID1 bis 64 aus a-z, 0-9, ., _ und -. Sie steht in Projektdateien und ändert sich nie. Eine andere ID wird mit einem Protokolleintrag übergangen; verwenden zwei Erweiterungen eine ID, wird keine verwendet.
Referenzfür RFiDGear undurchsichtig bis auf ihre Form: 1 bis 128 aus A-Z, a-z, 0-9, ., _, :, / und -. Eine Bindung mit anderer Form scheitert vor jedem Aufruf. Was sie bedeutet, bestimmt der Anbieter.
Erzeugungeine Instanz je Anbieter, auf dem Thread der Benutzeroberfläche, wenn der Host seine Registratur baut: der Konstruktor muss schnell sein und darf nichts anzeigen und auf nichts warten.
Threadsder Host ruft von Arbeitsthreads auf, möglicherweise mehrere zugleich, nie mit einem Synchronisationskontext. Seien Sie threadsicher.
Antworteine neue SecureKeyLease je Aufruf. Der Host besitzt sie und gibt sie frei; sie ist angeheftet und wird beim Freigeben genullt. Behalten Sie keine Kopien. ToHexString() macht eine Zeichenkette, die niemand nullen kann.
Gleiche Anfragederselbe Schlüssel innerhalb eines Laufs (RunId). Wechseln Sie Schlüssel zwischen Läufen, nie mitten in einem.
Fehlerein Fehler ist eine Antwort: SecureKeyResolution.Failed(grund). Ein Anbieter, der eine Ausnahme wirft, zählt als ProviderUnavailable. Schreiben Sie eigene Diagnosen und halten Sie Schlüssel aus ihnen heraus.
Zeitbeachten Sie das Abbruchzeichen: der Host wartet 10 Sekunden (5 Minuten bei einer Interactive-Anfrage) und verwirft einen Schlüssel, der später kommt. Eine Anfrage mit Interactive = false darf keine Eingabeaufforderung zeigen.
Unbekannter Algorithmusantworten Sie Unsupported. Der Host prüft die Länge jeder Antwort und beendet die Aufgabe mit KeyUnavailable, wenn sie nicht passt.

Die Plätze und Algorithmen

AufgabeAnfrage
MIFARE ClassicAlgorithm ist Classic6Byte (6 Bytes); der Bereich hat weder Applikation noch Schlüsselnummer; Usage ist Authenticate für Schlüssel, die einen Sektor öffnen, und ChangeKeyNew für die, die in einen Sector Trailer geschrieben werden. Der Sektor gehört nicht zur Anfrage, weil eine MAD-Operation einen Schlüssel für mehrere Sektoren verwendet.
Ultralight CPlatz ultralight.c.key, TripleDes2K (16 Bytes), Usage Authenticate
Ultralight EV1 und NTAGPlatz ultralight.password (UltralightPassword, 4 Bytes) und ultralight.pack (UltralightPack, 2 Bytes)
DESFiredie Schlüssel von PICC und Applikation; ein Platz, der an die SAM gebunden ist, ist kein Schlüssel und hat keine Bytes
Eine Erweiterung läuft in RFiDGear mit den Rechten des Benutzers und kann lesen, was die Anwendung lesen kann. Ein Anbieter ist keine Sicherheitsgrenze. Installieren Sie nur Anbieter, denen Sie vertrauen.

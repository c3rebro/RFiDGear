Die Grundsätze

  • Ein Versuch. RFiDGear wiederholt nie von selbst einen Befehl, der eine Karte ändert (schreiben, authentifizieren, formatieren). Ein Programm, das RFiDGear steuert, tut es auch nicht: meldet RFiDGear nach einem Zweifel nicht ausdrücklich „nie gestartet“, fragen Sie nach dem Ergebnis desselben Auftrags, statt ihn neu zu schicken.
  • Ein Prozess, ein Benutzer. Es läuft eine RFiDGear-Instanz je Windows-Sitzung. Die Pipe der externen Steuerung erreicht nur der Windows-Benutzer, der RFiDGear gestartet hat.
  • Verträge als Assemblies. Ein Client der externen Steuerung verwendet RFiDGear.Bridge.Contracts.dll, eine Erweiterung RFiDGear.Contracts.dll und RFiDGear.ExtensionSdk.dll; beide Gruppen behalten ihre Assemblyversion 1.0.0.0, damit früher gebaute Programme weiter binden. Die öffentliche Fläche ist durch freigegebene Schnappschüsse im Test festgehalten.
  • Nichts Geheimes im Protokoll. RFiDGear schreibt weder eine Variable noch einen Pfad, eine UID, einen Schlüssel noch den Text einer Ausnahme eines Clients in sein Protokoll.

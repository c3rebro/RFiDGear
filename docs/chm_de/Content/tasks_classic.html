MIFARE Classic

Die Aufgabe legen Sie mit Bearbeiten > Aufgabe erstellen / bearbeiten > Mifare Aufgabe > Mifare Classic Aufgabe hinzufügen/bearbeiten an. Sie liest und schreibt Blöcke und Sektoren eines MIFARE-Classic-Chips (1K, 4K und verwandte). Der Dialog öffnet sich nur, wenn ein Leser verbunden ist.

Die Aufgabentypen

AufgabentypWirkung
Daten lesenliest den Sektor mit den Schlüsseln des Dialogs (mit MAD Ben. die Anwendung über das MAD-Verzeichnis); die Daten erscheinen im Daten Editor unter Daten auf dem Chip
Daten schreibenschreibt Daten aus dem Zwischenspeicher auf den Chip. Was geschrieben wird, hängt von MAD Ben. ab: siehe „Was Daten schreiben schreibt“ unten
Sektor-Unbenutzt Prüfungprüft, ob der Sektor unbenutzt ist

Schlüssel und Zugriffsbits eines Sektors stehen im Sector Trailer, dem letzten Block des Sektors. Es gibt keinen eigenen Aufgabentyp dafür: Sie schreiben den Sector Trailer wie jeden anderen Block mit Daten schreiben.

Sector Trailer Editor

Der Reiter erscheint, solange die MAD nicht verwendet wird. Er zeigt unter Sector Trailer | Access Bits eine Tabelle der Zugriffsbedingungen eines Sektors. Die Spalten Read Key A, Write Key A, Read Access Bits, Write Access Bits, Read Key B und Write Key B sagen, welcher Schlüssel was darf. Sie wählen eine Zeile; RFiDGear rechnet daraus die drei Bytes der Zugriffsbits samt ihren Gegenstücken selbst aus.

Daten Editor

Zwei Tabellen: Daten auf dem Chip (was zuletzt gelesen wurde) und Daten im Zwischenspeicher (was Sie schreiben wollen). In der Auswahl legen Sie den Block fest, den Daten schreiben ohne MAD schreibt: Block 0, Block 1, Block 2 des Sektors oder den Sector Trailer. Die Schaltflächen Daten lesen und Daten schreiben führen die Aktion sofort an der Karte auf dem Leser aus, nicht als Teil eines Laufs; Datendatei Öffnen... lädt Daten aus einer Datei in den Zwischenspeicher.

Was Daten schreiben schreibt

EinstellungWas geschrieben wird
ohne MAD Ben.ein Block von 16 Bytes: der im Daten Editor gewählte Block des Sektors aus der Sektornummer. Wählen Sie den Sector Trailer, ändert das die Schlüssel und die Zugriffsbits des Sektors: Der Block wird dann so geschrieben, wie er im Zwischenspeicher steht. Das gilt nur für die Sektoren 0 bis 31. In den großen Sektoren 32 bis 39 nennt die Auswahl Sector Trailer den vierten Block des Sektors, einen Datenblock: er überschreibt Daten und lässt die Schlüssel, wie sie sind. Den Block 0 des Chips mit den Herstellerdaten schreibt RFiDGear nie.
mit MAD Ben.die Anwendungsdaten über das MAD-Verzeichnis. Dabei bekommen die Sektoren, die die Daten erreichen, auch die neuen Schlüssel und Zugriffsbits (Sektorschlüssel - Neu und die eingestellten Zugriffsbits); fehlt der Karte ein Verzeichnis, legt RFiDGear eines an. Die Daten kommen vor dem Verzeichnis, das Verzeichnis vor den Sector Trailern.
  • Ein Versuch. Jeder Schreibzugriff geschieht einmal, wird zurückgelesen und nie wiederholt. Der erste Block, der scheitert, beendet die Aufgabe. Ein Block, der nach dem Schreiben nicht so zurückgelesen wird, endet als Unbekannter Fehler.
  • Vorabprüfung. RFiDGear weist Zugriffsbits, die in sich nicht stimmig sind, und einen Block ohne 16 Bytes ab, bevor es einen Schlüssel an die Karte schickt.
  • Schlüssel B kann Daten sein. In der Auslieferungskonfiguration (Zugriffsbits FF078069) darf Schlüssel A den Schlüssel B lesen: B ist dann Datenbereich und kann sich nicht anmelden.
  • Nach einer Absage hält die Karte an. Verweigert ein Chip einen Zugriff, hält er die Karte an: der nächste Befehl scheitert einmal. RFiDGear weckt die Karte danach auf; der Fehler bleibt trotzdem ein Fehler der Aufgabe.

Das Ergebnis nennt, was fehlschlug: nur Authentifizierung fehlgeschlagen heißt, dass ein Schlüssel abgelehnt wurde; ein anderer Fehler bleibt ein anderer Fehler.

Falsche Zugriffsbits können einen Sektor für immer sperren, und mit dem Sector Trailer ändern Sie seine Schlüssel. Probieren Sie das zuerst an einer Karte, die Sie nicht mehr brauchen. Notieren Sie die neuen Schlüssel, bevor Sie schreiben.
Mit einem PC/SC-Leser ist bisher nur das Lesen an einer 4K-Karte ausprobiert. Die Schreibwege, die MAD und die Dialoge sind nur an einer Chip-Nachbildung im Speicher geprüft, mit einem Elatec TWN4 an keiner Karte. Prüfen Sie das Ergebnis jeder Schreibaufgabe an einer Testkarte, bevor Sie sie in einer Serie einsetzen.
